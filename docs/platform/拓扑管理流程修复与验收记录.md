日期：2026-11-18。基线 `d322fac`，本轮应用修复已加载到当前平台；源代码、验收记录与前一轮持久化维护调整一并归档提交。

## 修复后的操作流程

进入拓扑管理 → 新建或打开拓扑 → 从左侧选择模板或直接添加原生节点 → 在中间画布连接节点 → 在右侧配置服务、接口和链路参数 → 保存并重新打开 → 启动后在原工作区查看实际配置 → 停止或删除会话；历史记录保留。

- 首页统一发现已保存配置、未保存活动会话和历史配置。运行状态由 CORE 当前会话身份、drill_id 和状态联合核对，旧状态不会仅凭同号会话继续显示为运行。CORE 不可用时保留保存配置和历史读取，并提示状态待确认。状态附更新时间，外部操作后可使用“刷新状态”。
- 去掉独立“运行画布”入口，`#topo` 旧入口归入统一工作区。编辑配置、实际运行及历史配置明确区分；实际和历史视图只读，可回到下次运行配置或复制编辑。
- 节点库同时显示全部 Docker 模板和原生模板，点击明确的模板后添加，不再先添加第一项。原生主机、原生路由器、交换机、集线器和无线网络可直接添加，无需先建模板；CORE 原生服务与镜像服务分别编辑。
- 节点与链路同画布显示。点击“连线”后选择两个节点，右侧编辑端点接口、IPv4/IPv6、时延和带宽，提供高级参数；支持 Esc 取消、禁止自环和重复建链。选线命中范围加宽，节点移动时链路同步更新。节点与链路表保留为辅助视图。
- 保存和重新打开保留模板固定修订、节点覆盖及未知扩展字段。启动前提示新建会话和当前修改的保存行为。切换模块和离开未保存拓扑时保护编辑。
- 活动会话“保存为拓扑”建立保存配置关联，原会话运行不变，原始执行快照不改写。删除保存定义、删除会话后仍可在列表找到历史配置。
- 原生节点显示名与实际运行名分离：中文、空格、斜杠及重复显示标签不再进入 vnoded 命令/套接字名称。运行名按节点 ID 稳定生成，用户标签保留在绑定与拓扑配置中。
- 后端保存时拒绝无效的接口地址、掩码、接口 ID、MTU 和负数/越界链路参数，避免到启动阶段才失败。启动失败显示简要原因，详细诊断可以展开。
