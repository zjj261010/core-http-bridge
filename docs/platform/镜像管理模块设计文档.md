# 镜像管理模块 设计文档

> 版本：v1.0（2026-11-12）
> 定位：管理平台第一模块 —— 靶标交付物（镜像/服务定义/清单）全生命周期管理
> 运行环境：core-http-bridge（FastAPI/uvicorn）+ Docker + CORE 9.2.1 daemon
> 架构前提：**路线 B**（服务由 CORE 声明启动）+ **不运行时切换**（模式固化于镜像 tag，部署前选型、运行中冻结）+ **无验证门禁**（漏洞是否存在由演练过程回答）

---

## 1. 概述与职责边界

### 1.1 模块定位

镜像管理模块管理**靶标包**——完整交付物 = 基座镜像 + CORE 服务定义 + 配方清单，三位一体。管理单元不是狭义的"docker 镜像"，而是"一套可声明、可启动、可复现的靶标交付物"。

### 1.2 四方职责边界（决策权分配）

| 层 | 决定权 | 类比 |
|:--|:--|:--|
| **构建平台/配方库** | 有什么服务可声明（服务注册 + 与镜像绑定） | 弹药库 |
| **镜像管理模块（本文档）** | 交付物的进出、登记、启停、删除 | 军械管理员 |
| **想定** | 声明该节点启动哪些服务 | 作战命令 |
| **CORE** | 按声明执行（投递/启动/校验/停止） | 发射装置 |

### 1.3 明确不做的事（职责外）

- ❌ 不探测/不判定镜像"是否真的有漏洞"（演练过程回答，平台不做自动漏洞验证）
- ❌ 不提供运行时模式切换（想定声明即冻结；改模式 = 停止销毁 → 改想定 → 重部署）
- ❌ 不强制 bundle 整包原子导入（三件独立、允许缺件、手动补录——支持外源镜像）
- ❌ 不限制镜像来源（打包导入/外源导入均可，来源仅作登记）

## 2. 核心概念与数据模型

### 2.1 靶标包（Target Bundle）—— 交付物单元

```
<靶标名>-bundle/
├── image.tar                # 基座镜像（docker save：软件+配置装好，不自启）
├── manifest.json            # 配方清单（权威绑定：软件/CVE/服务/端口/锚点/flags 可选）
└── services/
    ├── svc-httpd-41773-vuln/
    │   ├── service.py                   # CORE 服务定义类
    │   └── templates/httpd-41773-vuln.sh  # 启动脚本模板（Mako）
    └── svc-httpd-41773-normal/
        ├── service.py
        └── templates/httpd-41773-normal.sh
```

### 2.2 manifest（配方清单）Schema

```json
{
  "name": "dmz-es1427",
  "software": "elasticsearch",
  "version": "1.4.2",
  "cve": ["CVE-2015-1427"],
  "image": { "name": "target-dmz-es1427", "tag": "v1", "ports": [9200] },
  "services": [
    { "name": "svc-es1427-vuln",   "mode": "vuln",   "startup": "bash /opt/scripts/start.sh", "depends": ["elasticsearch"] },
    { "name": "svc-es1427-normal", "mode": "normal", "startup": "bash /opt/scripts/start.sh", "depends": ["elasticsearch"] }
  ],
  "flags": [ { "name": "flag1.txt", "path": "/flag1.txt", "requires_root": true, "score": 1 } ],
  "anchor": { "vuln": "curl -s http://127.0.0.1:9200/_search -d '...'", "expect": "flag 可达" },
  "notes": "人工编目时填写的备注"
}
```

### 2.3 服务命名规范（正式）

```
服务名 = svc-<软件>-<CVE或能力>-<模式>
  模式 ∈ {vuln, normal}      成对注册、同软件互斥、缺省 normal（安全默认）
group = drill/<网段位置>/<漏洞类别>        （分类展示用，非约束）
```

### 2.4 数据模型（平台库）

```
targets（靶标/实例表，混合拓扑：docker 与 netns 两类节点实例）
├── name, runtime_type (docker | netns)                       # 🆕 运行时类型（CORE 原生混合拓扑，实测已验证）
├── image_tag（仅 docker 型有；netns 型共享宿主 rootfs，无镜像）
├── import_source(packaged|external)
├── pieces: { image: bool, services: bool, manifest: bool }   # 三件各自到位状态（netns 型无镜像件）
├── services: [{name, mode}]                                  # 绑定的服务清单（权威绑定；netns 型服务经 vcmd 天然可用）
├── manifest: JSON                                            # 同步自导入/手动编辑
├── ports: [int], cve: [str], flags: [JSON]
├── verify_status: unverified|verified                        # 兼容字段(人工验证结论, 非门禁)
├── created_by/at, updated_at
services（服务注册表）
├── name(全局唯一), mode, software, cve, ports
├── definition_file(源文件路径), bound_targets[]
manifest_versions（清单历史, 可选）
audit_log（操作审计）
```

## 3. 接口设计（REST）

### 3.1 端点总表

| 方法 | 路径 | 作用 | 备注 |
|:--|:--|:--|:--|
| POST | `/targets/import/image` | 镜像导入 | body: 服务器路径或 multipart tar → docker load |
| POST | `/targets/import/services` | 服务定义导入 | .py + templates/ 成对上传 → 复制到 custom_services_dir |
| POST | `/targets/import/manifest` | 清单导入（JSON） | 入配方库 |
| POST | `/targets/{name}/manifest` | 手动补录/编辑清单 | 表单提交 |
| POST | `/targets/{name}/services` | 手动补录服务定义 | 单服务声明文件 |
| GET | `/targets` | 全量列表 | **含三件完整性状态列** |
| GET | `/targets/{name}` | 靶标包详情 | 三件状态 + manifest + 服务对 |
| DELETE | `/targets/{name}/image` | 镜像删除 | 占用检查 → 拒绝或确认 |
| DELETE | `/targets/{name}/services/{svc}` | 服务定义删除 | 引用检查 → 告警 |
| POST | `/targets/{name}/run` | 独立启动容器（普通隔离，验证用） | 不接 CORE 网络 |
| POST | `/containers/{name}/stop` | 停止容器 | 仅独立容器 |
| DELETE | `/containers/{name}` | 删除容器 | 仅独立容器 |
| WS | `/containers/{name}/terminal` | 容器终端（docker exec -it） | 审计留痕 |
| POST | `/containers/{name}/exec` | 容器内执行命令 | 审计留痕 |

### 3.2 统一响应与错误码

```json
{ "ok": true|false, "data": {...}, "error": { "code": "...", "message": "...", "detail": "..." } }
```

| 错误码 | 场景 |
|:--|:--|
| IMAGE_CONFLICT | 镜像名已被容器引用（删除被拒） |
| SERVICE_DUPLICATE | 服务名与已注册服务重名（上传预检） |
| SERVICE_IN_USE | 服务定义被想定引用（删除告警，不硬拦） |
| PIECE_MISSING | 三件缺失（导入/操作前置检查） |
| MANIFEST_INVALID | 清单校验失败（缺必填/服务名不合规范） |
| MODE_INVALID | 模式非 normal/vuln |

## 4. 状态机

### 4.1 靶标包状态（三件独立跟踪，缺件 = 状态而非错误）

```
         ┌─── 镜像: 未导入/已导入
导入 ────┼─── 服务定义: 未注册/已注册
         └─── 清单: 未编目/已编目
                ↓
完整性视图 = 三件取与: 完整/缺件(列明缺什么)     ← 缺件是正常状态, 不是错误
```

### 4.2 容器生命周期（独立容器）

```
创建(run) → 运行 → 停止(stop) → 删除(delete)
                ↑ 崩溃/退出 → Exited（可再 start）
CORE 拓扑容器不在本状态机内（随 CORE 会话生命周期）
```

### 4.3 模式生命周期（路线 B 定稿：无运行时切换）

```
部署前: 选 tag（v3-normal / v3-vuln）→ 想定声明对应服务
   ↓
运行中: 模式冻结（不可变, 无切换入口）
   ↓
停止销毁 → 改想定（换服务声明）→ 重新部署（新模式的同构环境, IP/拓扑不变）
```

## 5. 关键流程

### 5.1 外源镜像导入 + 手动补录（鲁棒性主流程）

```
① 导入镜像 tar → docker load → 镜像 ✓（服务定义 ✗ / 清单 ⚠️未编目）
② 操作员独立启动（run）→ 进终端/exec 探测：有什么服务、什么端口、怎么启动
③ 手动补录清单（表单/JSON）→ 清单 ✓
④ 手动补录服务定义（vuln/normal 启动脚本 + 定义）→ 上传 → 维护窗口重启 daemon → 服务 ✓
⑤ 完整性视图转"完整" → 可进入正式想定
```

### 5.2 漏洞演练执行（想定决定模式）

```
想定声明 node.services = ["svc-httpd-41773-vuln"]
   ↓ CORE 实例化
容器创建 → 服务文件 docker cp → 服务脚本执行 → 漏洞出现（vuln 态）
   ↓
红方按盲测方法论攻击（旗标/数据）→ 复盘报告
```

### 5.3 加固演练（改想定重部署，非运行时切换）

```
停止销毁当前环境 → 想定服务声明 DmzVuln 改为 DmzNormal → 重新部署
   ↓
同一攻击链重放 → 预期全链失效（穿越读 403 / RCE 403）→ 防御有效性量化
```

## 6. 安全与审计

| 控制点 | 措施 |
|:--|:--|
| 镜像导入（任意代码入口） | 来源登记、digest 校验、导入后隔离标记（未编目不得进正式想定） |
| 独立启动容器 | 普通隔离（非 privileged），与 CORE 拓扑启动区分 |
| 终端/exec（高危） | 审计留痕（when/container/cmd） |
| 服务注册/变更 | 影响所有想定的可见服务集 → 维护窗口批量生效 + 变更留痕 |
| 模式声明（vuln） | 显式动作留痕（想定文件即凭证） |
| 容器删除 | 仅限独立容器；CORE 拓扑容器随会话生命周期 |

---

## 7. 非功能要求

| 维度 | 要求 |
|:--|:--|
| 鲁棒性 | 三件独立导入、部分状态一等公民（缺件可见可补）、失败互不传染 |
| 长任务 | docker load/build 异步化（job + 轮询/SSE 进度），不阻塞接口 |
| 一致性 | 平台配方库 ↔ 镜像 label ↔ daemon 注册表三方可对账 |
| 存储 | 镜像归档进持久目录（/opt/artifacts 风格），/tmp 仅过程文件 |
| 审计 | 全部变更类操作留痕（who/when/what/old→new） |

## 8. 页面原型（镜像管理页面，Tab1）

### 8.1 镜像列表页（Tab1 主页面，表格展示）

**表格列定稿（四列）**：镜像名 / 大小 / 导入时间 / 操作（详情、删除）。**无模式列**——模式由想定声明决定（部署前选型），本页面不展示；软件/CVE/端口/三件完整性等信息在**详情抽屉**（点击行或"详情"进入）。

```
┌──────────────────────────────────────────────────────────────┐
│ 镜像管理                                   [导入镜像] [导入服务定义] │
├──────────────────────────────────────────────────────────────┤
│ 镜像名       大小     导入时间          操作                  │
│ dmz-es1427   212 MB   2026-11-12 15:55  详情 | 删除            │
│ redis-unauth 262 MB   2026-11-12 16:02 ⚠缺清单 详情 | 删除     │
│ ...                                                          │
└──────────────────────────────────────────────────────────────┘
```

### 8.2 靶标详情抽屉（点击行/详情进入）

- 三件完整性（镜像/服务定义/清单各自状态）
- 软件/漏洞信息（软件/版本/CVE/端口）
- 服务定义对（vuln/normal 成对展示）
- manifest 编辑（JSON 表单）
- 独立容器（验证用启动/终端/exec 入口）

### 8.3 导入向导

三步：选 tar/填路径 → （可选）选同名 manifest → 导入结果（三件落位状态 + 缺件指引）

## 9. 与其他模块的关系

| 模块 | 衔接 |
|:--|:--|
| AgentCyTE 想定编辑器 | 服务下拉框 = 本模块清单接口渲染（清单驱动声明） |
| 监测平台 | 消费本模块的容器/镜像视图；对账 CORE 声明 vs 容器实际 |
| bridge 既有能力 | 管控平面（会话/节点/链路）不变，本模块是镜像维度的补充 |
