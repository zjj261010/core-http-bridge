# 部署与回滚

默认配置保持兼容。可通过 `CORE_GRPC_ADDRESS`、`BRIDGE_HOST`、`BRIDGE_PORT`、`BRIDGE_DATA_DIR`、`BRIDGE_DB_PATH`、`CORE_CUSTOM_SERVICES_DIR`、`BRIDGE_IMPORT_DIR`、`BRIDGE_TEMP_DIR` 指向独立环境。应用与 CORE daemon 应共享临时目录和服务目录的文件系统；运行用户应具有对应读写权限。

首次读取旧清单、模板和想定登记时，在原目录生成 `.pre-sqlite.bak`，校验记录内容后以 SQLite 为唯一写入来源。原 JSON 保留但不再更新。停止 Bridge 后备份数据库（包括 WAL，或使用 SQLite backup API）。回退旧程序前，将备份 JSON 复制回原路径；回退会放弃迁移后新写入的数据，请先保留数据库副本。

靶标版本固定镜像 ID、能力清单和服务定义。模板修改创建新版本。草稿保持所选模板版本，只有“升级模板版本”并确认差异才改变引用。部署快照和旧版本继续保留。服务定义以版本专用名字注册到 CORE；不自动重启 daemon。已删除的镜像 ID 需重新导入后才能部署旧版本。

以 root 执行 `scripts/core-network.sh --install`，会备份现有规则及 systemd 单元，安装四种 CORE `p.+`/`b.+` 网桥之间的 IPv4/IPv6 FORWARD 规则；不会修改默认策略。输出备份目录。检查使用 `--check`。回滚运行 `scripts/rollback-network.sh <备份目录>`，仅移除本工具标注的规则并恢复旧单元，不覆盖其他服务后来增加的规则。

无须重启 CORE daemon。更新 Bridge 前确认后台导入任务完成；被重启打断的任务在下次启动显示 interrupted，可由导入页面续办。生产部署应先检查活跃会话，避免终端和 SSE 连接被 Bridge 重启断开。

原生 XML 通过 session_metadata 携带平台绑定，导入时为容器生成新运行名并保留版本。来自其他平台而缺少相应模板版本的 XML 会明确提示先补齐交付物；没有平台元数据的 XML 作为独立配置导入，不根据节点名字猜测模板。
