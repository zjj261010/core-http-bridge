# 计划逐项复核与剩余工作

状态：下表保留上一轮静态复核的原始发现。本轮已实施这些缺项，最新状态见 [剩余项实施与验收记录](剩余项实施与验收记录.md)；用户批准的四项定向补验已通过，生产更新与资源清理完成。下表为修正前发现，不能当作当前缺陷清单。

此前 A0～A6、B1/B2 全部完成的标记过于宽泛。107 项真实场景的结果仍有效，但没有覆盖下面所有计划要求，不能用通过数替代完整交付。

| 对应计划 | 代码核对发现的剩余工作 | 实际影响 |
| --- | --- | --- |
| A1 事件按钮 | 离开 Tab/面板时的释放逻辑尚未完整覆盖 | 页面可能保留不再展示的订阅 |
| A2 §5.2.5～6 | 同名更新的影响范围、已落盘/待生效/daemon 已注册的完整展示 | 用户不能从页面准确判断更新影响和当前生效状态 |
| A3 §6.1～6.2 | 定义态替换/修改后，当前绑定与原部署 source/snapshot 的一致性需完善 | 从历史重新部署可能沿用原定义；不能一概宣称冻结快照与编辑后的状态一致 |
| A4.1、5、8 | jobs.run 在整个导入返回后才保存 result；resume 仅复用镜像，服务和清单仍重新执行 | 中途完成的件可能未落库，尚不具备完整按件恢复语义 |
| A4.8 | resume 校验旧输入后允许合并新 manifest，却按旧 ref 决定复用镜像 | 改变清单镜像声明时尚缺少新旧件对应校验 |
| A5 §8.1.5～6 | 身份不可取得时缺少完整“归属待确认”展示；active 身份和引用未具备计划要求的数据库唯一约束 | 目前主要依赖进程内锁；计划要求的数据库级一致性尚未闭环 |
| A5 §8.2 | monitor.html 先发起历史 fetch，再建 EventSource，没有事件去重 | 历史和实时交叠或初始化窗口可能出现重复、乱序或遗漏 |
| B1 | 已有版本历史与显式升级；publication_state 是查询时统一标记 published，尚无完整持久化草稿/发布状态流程 | 完整发布生命周期尚未实现 |
| B1 | 删除检查包含活跃引用和草稿，尚未列出历史快照引用；未提供从历史快照直接新建草稿的完整入口 | 历史复用和删除影响说明不完整 |
| B2 | JSON 已迁入 SQLite，但版本发布、集合更新、引用维护仍分属不同事务，引用未形成完整数据库约束 | 尚不能称计划要求的一致性事务和约束全部实现 |

以上是已静态确认的剩余项，并非宣称其他边界已经全量验收。实施时应继续按原测试规则，先集中阅读与修复，再对新增或必要受影响场景安排最小验证。
