## 走查范围与现场数据

用真实 Chromium 操作当前平台 `http://192.168.197.202:8080/#topologies`。依次进入拓扑管理、打开“运行画布”、返回并新建未保存拓扑、点击添加模板节点、添加交换机、切换链路页签、尝试添加链路、返回节点画布。所有编辑仅在浏览器内存中，未保存、启动、停止或删除会话。没有注入模拟 API 数据。

当前接口返回：保存拓扑 0、运行记录 0、CORE 会话 0、模板 0；可用服务中的 system 项有 23 个。因现场没有模板，“添加模板节点”提示“请先创建节点模板”，随后等待模板选择器超时，未重试。浏览器无未捕获页面异常。因只有一个交换机，添加链路提示“至少需要两个节点”；这次没有实际建立链路。

因此，用户所述“空列表但有拓扑在跑”和“只有一个 Docker 模板”不是本次现场复现的状态，不填写为已复现；下面相关结论明确来自代码阅读。

## 问题与原因

| 问题 | 证据 | 使用影响 |
| --- | --- | --- |
| 保存拓扑与实际运行对象脱节 | `topology-manager.js::load` 分别读取 `/topologies` 和 `/deployments`；`topologies.py::for_session` 可生成没有 topology_id 的运行记录 | 直接在会话画布建立或导入的对象不会自然出现在保存拓扑列表；用户难以判断自己管理的究竟是什么 |
| 历史状态没有核对实时会话 | 拓扑管理未查询 `/api/sessions`，运行记录直接显示持久 status；当前没有记录可现场复核 | 有记录时可能将过去的状态当成当前状态，须用身份和实时数据判断，不能只凭会话号关联 |
| 两套画布、两套操作顺序 | 点击“运行画布”后从嵌入的拓扑编辑器转到根页面 `#topo`，再要求选择或新建会话 | 未选择拓扑就进入空画布，不说明保存配置与实际会话的关系，返回后又回到列表 |
| 添加模板节点没有先选择 | `addNode` 直接使用 `templates[0]`；模板下拉框藏在已添加节点的参数区 | 有多个模板也先添加第一个，之后才能替换；本次模板为零，实际得到报错 |
| 原生节点缺少直接入口 | 新建拓扑只有“添加模板节点”和“添加交换机”；非模板节点编辑器只显示只读说明 | 即使 CORE 支持原生节点和服务，也必须绕去创建模板或导入文件；不能自然添加主机或路由器 |
| 节点和链路被拆到互斥页签 | 点击“链路与接口”后画布消失；画布上的线仅展示，不支持直接选择或创建 | 看不到布局时填写端点，不能在图上连续完成摆节点、连线、改接口 |
| 缺少上下文和就地提示 | 当前空拓扑仍显示“删除”；节点不足仍可点“添加链路”，错误出现在整页顶部；旧画布仍有“实例”“靶标容器”措辞 | 用户需要点击失败后才知道前提，且术语与当前镜像/模板模型不一致 |

这次实际走查说明：此前合并导航并没有实现操作流程的一致性，不能据此前功能测试通过就认为拓扑管理交互已完成。

## 修正顺序与目标流程

1. **统一拓扑入口和状态。** 首页提供清晰的名称、节点数、真实运行状态、更新时间和打开操作。保存定义、活动会话和历史记录可以保留各自数据模型，但须在一个拓扑上下文中关联展示。没有保存定义的活动会话以“未保存配置”显式出现，允许打开和另存；旧记录无法恢复时说明原因。会话号可复用，实时关联须同时核对 drill_id 等身份，不将历史会话号直接当成当前运行实例。
2. **一个拓扑工作区。** 从列表打开后一直保留当前拓扑身份和画布。工具栏提供保存、导入导出、启动/停止；明确显示当前查看的是编辑配置还是某次实际运行。去掉独立“运行画布”入口。多次运行可选择查看，每次运行记录归属于当前拓扑；历史总览作为次级入口保留。编辑只影响下一次运行，不默默改变运行中的配置。
3. **完整节点面板。** 左侧同时提供 Docker 模板、原生模板、可直接使用的原生主机/路由器和交换机/集线器/WLAN 等网络构件。模板先选择再添加，可搜索并展示运行类型。直接原生节点无需预建模板，可在右侧配置模型和 CORE 服务；Docker 节点的镜像服务继续与 CORE 原生服务分开。当前支持范围外的类型不能伪装为可用。
4. **节点与链路同画布。** 左侧添加节点，中间摆放和连接，右侧编辑选中对象。进入连线模式后依次点击两个节点，明确显示首端点，可取消；点击线后在侧栏编辑接口、IP 和网络参数。端点、自环和重复链路即时校验，批量节点/链路表作为辅助视图，不取代画布。默认接口分配及地址规则需与后端一致。
5. **收拢提示和旧入口。** 空列表说明下一步；依赖不足时按钮禁用并解释原因。未保存修改有清晰标记，切换对象时保护编辑；启动前展示即将创建的运行及配置摘要。旧链接定位到统一工作区相应对象，表单继续不用 JSON 编辑器。

目标操作顺序：拓扑列表 → 新建/打开 → 同画布添加 Docker 或原生节点 → 点两个节点连线 → 侧栏修改节点服务或链路接口 → 保存 → 启动 → 原画布查看实际运行；历史记录在该拓扑内查看。
