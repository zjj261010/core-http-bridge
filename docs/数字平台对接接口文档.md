# 数字平台对接接口文档

> 版本：**V2.0 查询模式**（2026-11-24，随 core-http-bridge 实现态编写，端到端实测通过）
> 读者：数字平台（智能训练＋推演评估系统）开发与联调人员。
> 定位：本文档是**容器平台（CORE ＋ core-http-bridge）作为提供方**的对接规格——覆盖攻击动作序列下发（IF-01）＋三个查询接口（Q1 任务状态 / Q2 执行结果 / Q3 Snort 告警）的**已实现**行为。
> **V2.0 变更**：结果与告警由"容器平台推送（IF-02/IF-03）"改为"容器平台持久化保存、数字平台主动查询（Q1/Q2/Q3）"。回调地址/回调 Token 配置**取消**。设计依据与差异对照见《docs/design/数字平台与容器平台交互设计V2.0-查询模式.md》。
> 一期实现边界：可执行动作仅 `HttpServiceCheck`（预置 HTTP 服务检查）。红方动作空间全量映射（ExploitRemoteService 等）为独立需求，未实装——字典条目已预留扩展位（§7）。

## 1. 对接前置条件（容器平台侧配置）

| 配置项 | 环境变量 | 说明 |
|:--|:--|:--|
| ~~入向鉴权~~ | `BRIDGE_VALIDATION_TOKEN` | **已关闭（2026-11-24 定稿）**：接口组默认不鉴权——无凭据/错误凭据均放行，访问控制靠**内网隔离＋端口准入**（同平台整体安全模型，无 RBAC）。该变量变为**可选加固开关**：配置后 IF-01 启用 Bearer 校验（错误凭据 401/1000），删除并 restart 即恢复开放。Q1/Q2/Q3 查询接口恒开放 |
| ~~出向回调地址~~ | ~~`BRIDGE_VALIDATION_CALLBACK_URL`~~ | **V2.0 取消**——拉模式无推送，容器平台无需知道数字平台地址。存量配置不再被读取 |
| ~~出向回调鉴权~~ | ~~`BRIDGE_VALIDATION_CALLBACK_TOKEN`~~ | **V2.0 取消**，同上 |

以上为容器平台 core-bridge 服务的进程环境变量（systemd `Environment=` 或 drop-in 配置），变更后 `systemctl restart core-bridge` 生效。

**拓扑侧前置要求**（部署时固化，任务受理前置校验项）：

| 标记 | 节点属性 | 约束 |
|:--|:--|:--|
| 序列执行节点 | `validation_source = true` | 每拓扑至多一个；须为本机 CORE 原生节点或 Docker 节点；所有动作由该节点发起 |
| HTTP 验证目标 | `validation_http_port`（1–65535） | 每拓扑至多一个；目标节点声明此端口表示"该端口上有可验证的 HTTP 服务" |

标记方式：容器平台拓扑编辑页节点属性勾选/填写（`validation_source` / `validation_http_port` 字段），或建节点 API 直接传字段；保存进拓扑修订、部署时固化到运行快照。旧拓扑无标记仍可正常运行，但要受理验证任务必须部署带标记的修订（否则 409/1003）。

**Snort 观测（可选）**：拓扑定义 `network_activity.probes` 声明探针（原生/Docker 节点接口被动抓包，内置 `verification` 无害验收规则集），运行期容器平台将窗口内告警结构化入库。未部署探针的任务照常受理与执行，仅 `observation_status=unavailable` 且 Q3 恒为空。

## 2. IF-01 攻击动作序列下发（保留，V2.0 无接口变化）

```
POST /api/v1/attack-sequences
Content-Type: application/json; charset=utf-8
```

鉴权默认关闭（见 §1）：无需 `Authorization` 头；仅在容器平台配置了 `BRIDGE_VALIDATION_TOKEN` 时才校验 Bearer 凭据。

### 2.1 请求报文

```json
{
  "scenario_id": "1",
  "sequence_id": "demo-001",
  "actions": [
    {
      "seq": 1,
      "action_name": "HttpServiceCheck",
      "target_node": { "subnet": "10.99.0.0/24", "ip": "10.99.0.1" },
      "params": { "check_id": "web-health" }
    }
  ]
}
```

### 2.2 字段规格

| 字段 | 类型/约束 | 说明 |
|:--|:--|:--|
| `scenario_id` | 十进制正整数字符串 | **即容器平台当前运行中的 CORE session_id**。数字平台经会话查询接口取得运行会话后原样传入；容器平台校验其处于运行态 |
| `sequence_id` | 非空字符串 ≤128（`[A-Za-z0-9_.-]`） | 每次新任务全新生成（建议 UUID）。幂等键 = (scenario_id, sequence_id)：同键同文返回原回执；同键异文 409/1005 |
| `actions[]` | 1–64 步 | 按 seq 排序后必须为 1…N 连续，重复/缺号拒绝（1004） |
| `actions[].seq` | int ≥1 | 执行顺序 |
| `actions[].action_name` | ≤64 字符 | 必须在动作字典目录内（当前可执行：`HttpServiceCheck`）；未知动作 1002 |
| `actions[].source_node` | 可省略 | 省略时使用部署标记的序列执行节点；提供时与标记节点接口核对（subnet/ip 须匹配），不匹配报 1003 |
| `actions[].target_node` | 必填 `{subnet, ip, hostname?}` | 必须对应本次部署标记的 HTTP 验证目标（subnet/ip 核对，须为该节点接口上的地址且部署内唯一）；IP 为合法 IPv4 字面量 |
| `actions[].params.check_id` | 默认 `web-health` | 当前仅接受 `web-health`（场景预设检查项） |

### 2.3 受理响应

```json
HTTP 200
{ "code": 0, "message": "accepted", "scenario_id": "1", "sequence_id": "demo-001",
  "dictionary_version": "validation/2" }
```

- `code=0` 表示已受理并完成预校验（此时**尚未执行**——实际 HTTP 可用性在步骤内判定）。
- `dictionary_version` 受理时钉定的字典版本，随 Q2 原样回传。
- 受理后容器平台**异步执行**，数字平台用 Q1 轮询进度；**数据保存承诺**：任务/步骤/告警全部持久化（SQLite），数字平台离线期间数据不丢失，恢复后查询即得全量。

### 2.4 错误码（IF-01，实测值）

| code | HTTP | 触发条件 | 数字平台处理 |
|:--|:--:|:--|:--|
| 1000 | 401 | 调用凭据无效（**仅当容器平台配置了 `BRIDGE_VALIDATION_TOKEN` 时**才可能出现；默认鉴权关闭不会返回） | 检查凭据配置或请容器平台移除 Token 配置 |
| 1001 | 409 | 会话不存在/未运行；或会话运行实例已变化（重启/复用）；或该 CORE 会话缺少运行中的 Bridge 部署 | 中止本次实测，确认会话后重发新 sequence_id |
| 1002 | 400 | 动作名不在字典目录内（或为仅供对照的参考条目） | 中止并告警，核对字典版本 |
| 1003 | 409 | 源/目标节点未标记、已离开会话、请求地址与运行接口不匹配、目标地址在部署内不唯一 | 检查拓扑标记与请求地址一致性 |
| 1004 | 400 | 请求格式无效（缺字段/类型错/seq 不连续/超出上限 64 步） | 修正报文 |
| 1005 | 409 | 相同幂等键但报文内容不同 | 冲突：核对 sequence_id 是否复用 |
| 1006 | 409 | 该会话已有未完成的验证序列（一期每会话串行执行一个序列） | 等待当前任务完成（Q1 轮询） |
| 1501 | 503 | 验证接口未启用 / CORE 会话状态暂不可确认 | 容器平台侧配置或 CORE 状态问题，联系运维 |

注意校验顺序：请求格式校验（1004）先于鉴权（1000，仅启用时）执行——格式非法的报文即使凭据正确也返回 400/1004。

## 3. 任务执行语义（容器平台内部行为，供数字平台理解查询数据）

受理后容器平台按以下语义自动执行，数字平台无需再下发任何指令：

1. **执行节点**：全部动作在部署时标记的 `validation_source` 节点内执行（nsenter 进入其网络命名空间）；源节点 IP 即该节点在拓扑中的接口地址。
2. **逐步记录**：每步记录 started/ended（UTC RFC3339 毫秒）、duration_sec（单调时钟）、exit_code、reason。
3. **失败即停**：某步 FAIL 后后续步骤记 SKIPPED（reason 注明前序失败）。
4. **观测窗口**：任务受理时记录 Snort 探针基线与事件游标；执行窗口 = 第一步开始至最后一步结束＋收集宽限期（2s）。窗口内、命中部署内 Snort 探针、且源/目的五元组可唯一归属某步的告警，标记 `seq` 归属该步；无法唯一归属的告警 `seq=null` 保留在窗口观测中。
5. **观测状态**：`complete`（探针覆盖整个窗口）/ `partial`（有缺口或丢包）/ `unavailable`（无运行探针）。探针部署见《接口文档-外部调用版.md》§2.1.7 network_activity 声明。
6. **会话异常**：会话停止/被替换/容器平台中断时，任务立即封存——已完成步骤保留事实，中断且无法确定结果的记 FAIL（reason=interrupted_outcome_unknown），随后照常可查。
7. **结果不可变（数据冻结承诺）**：`finished` 后 Q1/Q2/Q3 返回内容不再变化（`observation_status` 也回放封存值，不随探针后续状态漂移）；重复查询完全幂等。

一期动作的判定基准：`HttpServiceCheck` 对目标 `<ip>:<port>` 发起受限 HTTP GET——HTTP 2xx 且退出码 0 → SUCCESS；连接失败/超时 → FAIL（reason=http_check_failed / http_check_timeout）。

## 4. Q1 任务状态与步骤查询（V2.0 新增）

```
GET /api/v1/attack-sequences/{sequence_id}?scenario_id={scenario_id}
```

**用途**：随时查询任务执行进度，决定何时拉取 Q2/Q3。建议轮询间隔 2–5 秒。任务未结束时也可查询（返回当前已发生的状态与步骤）。

```json
HTTP 200
{
  "data": {
    "scenario_id": "1", "sequence_id": "e2e-v2-003",
    "state": "finished", "observation_status": "complete",
    "dictionary_version": "validation/2",
    "source_node_id": 2, "target_node_id": 1,
    "steps": [
      { "seq": 1, "action_name": "HttpServiceCheck", "state": "SUCCESS",
        "reason": null, "duration_sec": 0.165 }
    ]
  }
}
```

| 字段 | 说明 |
|:--|:--|
| `state` | `accepted`（已受理待执行）/ `executing`（执行中）/ `finished`（已结束，结果冻结） |
| `observation_status` | 同 §3.5；任务未结束时实时推导，可为 null |
| `steps[].state` | `pending` / `running` / `SUCCESS` / `FAIL` / `SKIPPED` |
| `steps[].reason` | 失败/跳过原因（`http_check_failed` / `http_check_timeout` / `node_or_interface_unavailable` / `interrupted_outcome_unknown` / 前序失败说明）；成功为 null |
| `source_node_id / target_node_id` | 部署标记的执行节点/验证目标节点编号 |

任务不存在 → `404 {"code": 1001, "message": "任务不存在"}`。

**并发任务**：同一会话同时只有一个任务（1006 拒绝第二个），Q1 按 sequence_id 精确查询互不干扰。

## 5. Q2 执行结果序列查询（V2.0 新增，替代 IF-02）

```
GET /api/v1/attack-sequences/{sequence_id}/results?scenario_id={scenario_id}
```

**用途**：任务 `state=finished` 后拉取整条结果序列入库校准。**响应结构与 V1.0 IF-02 payload 一致**（数字平台入库代码可复用）。

```json
HTTP 200
{
  "data": {
    "scenario_id": "1", "sequence_id": "e2e-v2-003",
    "dictionary_version": "validation/2",
    "state": "finished", "observation_status": "complete",
    "results": [
      { "seq": 1, "action_name": "HttpServiceCheck", "actual": "SUCCESS",
        "exit_code": 0, "reason": null,
        "started_at": "2026-11-24T08:08:30.022Z", "ended_at": "2026-11-24T08:08:30.186Z",
        "duration_sec": 0.165, "source_node_id": 2, "target_node_id": 1,
        "stdout_digest": "HTTP 200" }
    ],
    "alerts_total": 1
  }
}
```

| 字段 | 说明 |
|:--|:--|
| `dictionary_version` | 受理时钉定的字典版本，原样回传 |
| `results[].actual` | `SUCCESS`（完成且符合判据）/ `FAIL`（已尝试失败）/ `SKIPPED`（前序失败被跳过） |
| `results[].exit_code` | 有真实退出码传整数；未启动或未知传 `null` |
| `results[].reason` | 跳过/失败原因，同 Q1 `steps[].reason`；成功为 `null` |
| `results[].started_at / ended_at` | UTC RFC3339 毫秒；未执行传 `null`；duration_sec 未执行传 0 |
| `results[].source_node_id / target_node_id` | 实际绑定的容器平台节点编号 |
| `results[].stdout_digest` | 输出摘要（如 `HTTP 200`），可选 |
| `alerts_total` | 观测窗口内告警总数（对账 Q3 `total`） |

**语义保证**：`finished` 后结果冻结，重复查询返回完全相同内容（可安全重复拉取）；`results` 条数与受理步数一致、按 seq 排列；任务未结束即查询返回当前已完成步骤（`state≠finished` 提示稍后再取）。

## 6. Q3 Snort 告警分页查询（V2.0 新增，替代 IF-03）

```
GET /api/v1/snort-alerts?scenario_id={scenario_id}&sequence_id={sequence_id}&after_event_id={event_id}&limit=100
```

| 参数 | 必填 | 说明 |
|:--|:--:|:--|
| `scenario_id` / `sequence_id` | 是 | 任务定位 |
| `after_event_id` | 否 | 增量游标：只返回该 event_id 之后的事件（首次查询不传，取全部）；非法格式 400/1004 |
| `limit` | 否 | 默认 100，上限 500（超出收敛到 500） |

```json
HTTP 200
{
  "data": {
    "scenario_id": "1", "sequence_id": "e2e-v2-003",
    "observation_status": "complete", "is_last": true,
    "total": 1, "after_event_id": "net-xxx:1889",
    "alerts": [
      { "event_id": "net-xxx:1889", "probe_id": "probe-verify", "seq": 1,
        "ts": "2026-11-24T08:08:30.168Z", "sid": "1:1000001", "priority": 0,
        "src_ip": "10.99.0.10", "src_port": 44350, "dst_ip": "10.99.0.1", "dst_port": 80,
        "proto": "TCP", "msg": "Bridge IDS verification" }
    ]
  }
}
```

| 字段 | 说明 |
|:--|:--|
| `observation_status` | `complete` / `partial` / `unavailable`（finished 任务回放封存值） |
| `is_last` | `true` 表示已到窗口末尾——把 `after_event_id` 游标推进到本响应值再拉一次得到空页即完成全量拉取 |
| `total` | 游标之后（含本页）的告警总数 |
| `after_event_id` | 本页最后一条的 event_id（空页时回显请求游标）——**下一页请求直接携带此值** |
| `alerts[].event_id` | 事件稳定标识（`<run_id>:<事件id>`），接收端去重键 |
| `alerts[].seq` | 可唯一归属某步时为该步 seq（按五元组＋步骤时间窗唯一归属）；否则 `null` |
| `alerts[].ts` | UTC RFC3339 毫秒，**抓包时间**（非入库时间） |
| `alerts[].sid` | 规则标识 `GID:SID`；`priority` 规则优先级 |

**保存期限提示**：窗口内告警随平台 events 表保留策略保存（90 天），数字平台应在任务 finished 后及时拉取入库。

## 7. 动作字典与漏洞标注对接（扩展预告）

当前可执行动作仅 `HttpServiceCheck`。动作映射表真实化后，`ExploitRemoteService` 等动作将按 `params.exploit_id` 映射到具体利用方式——**exploit_id 与靶标漏洞标注（`service_pairs[].cve`）的双向索引**如下（靶标库已实测素材，登记格式与《action-dictionary-drafts.json》一致）：

| exploit_id | 靶标镜像 | CVE | 命令模板要点 | 成功判据 |
|:--|:--|:--|:--|:--|
| shellshock_cgi | target-csle-shellshock:v1 | CVE-2014-6271 | curl UA 注入 `/cgi-bin/vulnerable` | 目标 /tmp 标记文件存在（注入命令须绝对路径） |
| heartbleed_ssl | target-csle-heartbleed:v1 | CVE-2014-0160 | nmap --script ssl-heartbleed | 输出 VULNERABLE |
| sqli_login_bypass | target-csle-sqli:v1 | — | curl POST `' OR '1'='1' --` | 响应含全部用户行/FLAG |
| proftpd_mod_copy | target-csle-proftpd-3306:v1 | CVE-2015-3306 | SITE CPFR/CPTO + curl | webshell 响应 uid=33 |
| phpmailer_10033 | target-csle-phpmailer-10033:v1 | CVE-2016-10033 | exploit.sh multipart POST | backdoor.php 响应 uid=33 |
| es_groovy_1427 | target-csle-es1427:v1 | CVE-2015-1427 | _search script_fields Math 绕过 | exec.value 含 uid=0 |
| sudo_14287 | target-csle-sudo-0426:v1 | CVE-2019-14287 | sudo -u#-1 find -exec | uid=0 |

外部系统按 `POST /targets/image/detail` 读取 `service_pairs[].cve`，即可把靶标漏洞清单映射进推演模型；字典真实化后此处格式保持稳定。

## 8. 联调与验收清单（V2.0 查询模式）

| 编号 | 场景 | 通过条件 | 实测 |
|:--|:--|:--|:--|
| 01 受理与执行 | 带 `validation_source`/`validation_http_port` 标记的运行拓扑下发预置检查 | IF-01 code=0；Q1 轮询 accepted→executing→finished；Q2 `results[0].actual=SUCCESS`、`stdout_digest="HTTP 200"` | ✓（2026-11-24，shellshock 靶标＋kali 执行节点真实 HTTP 200） |
| 02 告警与归属 | 拓扑带 Snort 探针（verification 规则集）执行检查 | Q3 返回真实告警（sid=1:1000001）、`seq=1` 正确归属、`observation_status=complete` | ✓ |
| 03 分页与游标 | limit=1 分页 → 推进 after_event_id → 拉到空页 | `is_last` 正确翻转；非法游标 400/1004；任务不存在 404/1001 | ✓ |
| 04 数据冻结 | 任务 finished 后重启容器平台服务再查询 | Q1/Q2/Q3 返回内容与重启前一致（observation_status 回放封存值） | ✓ |
| 05 校验与幂等 | 停止会话/缺标记/未知检查项/同键异文均有明确错误码 | 错误码表 §2.4 全覆盖 | ✓（单元测试 225 项含隔离库验收） |
| 06 失败与中断 | 验证服务不可用记 FAIL＋后续 SKIPPED；中断后已完成步骤可查 | reason 区分 `interrupted_outcome_unknown` / `bridge_interrupted` | ✓（单元测试） |
| 07 观测归属 | 背景流量并存时不确定归属的告警 seq=null；探针停止与零告警可区分 | 归属算法五元组＋时间窗唯一 | ✓（单元测试） |

容器平台侧已具备：Q1/Q2/Q3 端到端实测（真实 Snort 探针告警链路）、定向测试 226 项、隔离库验收。数字平台侧需实现：查询客户端（Q1 轮询 + Q2/Q3 拉取入库）——**无需**提供接收端地址与 Token，也无需管理任何凭据（鉴权已默认关闭）。
