# 镜像启动模式漏洞标注问题

2026 年 11 月 24 日在提交 `746a0f4` 上复现两处兼容问题。未标注模式会导致外部镜像详情漏掉整份服务清单。旧模式缺少 `cve` 字段时，切换漏洞状态会触发前端异常。两项均待修复。

## 1. 未标注模式导致外部镜像详情漏掉服务清单

**复现**

1. 在隔离数据库中，为同一测试服务配置三种手动启动模式，分别设为未标注、基线和带 CVE 编号的标注模式。
2. 发布配置后通过 `GET /image-services/detail` 重新读取，确认三种模式的 `vulnerable` 字段分别为 `null`、`false`、`true`。
3. 调用 `POST /targets/image/detail`。先只传 `ref`，再用相同镜像传入具体的 `target_name` 和 `target_version`。

| 调用方式 | 实测结果 |
| --- | --- |
| 只传 `ref` | HTTP 200，`manifest` 为 `null`，`service_pairs` 为空。 |
| 指定已发布版本 | HTTP 200，能读到全部三种模式和对应标注。 |

已发布的 V3 清单把未标注模式写成 `vulnerable: null`。通用清单校验仅接受布尔值，镜像索引因此跳过整份清单。依赖普通镜像详情的调用方会读不到该镜像的服务信息，即使其中只有一个模式未标注。 [清单生成](../image_services.py#L369-L375) · [清单校验](../delivery.py#L48-L52) · [镜像索引](../target_admin.py#L199-L221)

**验收条件**

清单校验接受三态值 `null`、`false`、`true`，并拒绝其他类型。包含这三种模式的镜像发布后，按 `ref` 查询和指定版本查询均能返回完整服务清单及已配置的 CVE 编号。已有发布记录也能读取，无需重新发布。

## 2. 历史启动模式切换漏洞状态时抛出异常

**复现**

1. 使用一条更新前保存的启动模式，其数据中缺少 `cve` 字段。
2. 在「镜像管理 → 镜像详情 → 服务详情 → 编辑 / 脚本」打开该模式。
3. 将「漏洞状态」从「未知」切换为「有」。

浏览器抛出 `Cannot read properties of undefined (reading 'length')`。切换回调直接读取 `mode.cve.length`，历史数据缺少该字段时会中断这一操作。在浏览器中用省略 `cve` 的历史模式数据复现了异常。 [状态切换逻辑](../static/image-manager.js#L229-L234)

**验收条件**

缺少 `cve` 字段的模式按空列表显示，切换三种漏洞状态、暂存、保存和重新打开均可完成。用户留空 CVE 时应保留空列表，已有 CVE 编号在编辑状态时应保留。

## 本次验证范围

23 项定向测试通过，浏览器确认动作字典显示 10 条记录且为只读。上述两项分别通过隔离 API 验证和浏览器兼容场景复现，覆盖了定向测试之外的交互路径。

## 修复记录（b5438da，2026-11-24）

两项均已修复：

- **问题 1**：`delivery.manifest` 校验接受三态 `vulnerable ∈ {true, false, null}`（null=未标注），未标注模式不再跳过整份清单。三态清单回归验证通过。
- **问题 2**：前端切换回调 `(mode.cve||[])` 空数组兜底，历史数据缺 `cve` 字段不再抛异常。

服务命名规范另立设计稿：《服务命名规范》（artifacts/core-drill/），含包名/服务名文法、现役对照与禁则。
