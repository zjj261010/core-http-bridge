# 动作序列接口文档（V2.0 查询模式）

> 版本：V2.0 · 2026-11-24 · 随 core-http-bridge 实现态编写（commit `27fad67`），全部示例经真实环境执行验证
> 定位：**动作序列接口组的完整接口规格**——攻击动作序列下发（IF-01）＋三个查询接口（Q1 状态 / Q2 结果 / Q3 Snort 告警），供数字平台（智能训练＋推演评估系统）开发与联调直接使用
> 背景文档：接口形态设计依据见《docs/design/数字平台与容器平台交互设计V2.0-查询模式.md》（V1.0→V2.0 推改拉的动因与差异对照）；闭环校准与动作字典的集成上下文见《docs/数字平台对接接口文档.md》
> 一期实现边界：可执行动作仅 `HttpServiceCheck`（预置 HTTP 服务检查）；ExploitRemoteService 等红方动作为已立项演进项

## 0. 快速上手（五步时序）

```bash
BASE=http://<容器平台地址>:8080

# ① 下发动作序列（IF-01，受理即异步执行）
curl -s -X POST $BASE/api/v1/attack-sequences -H 'Content-Type: application/json' -d '{
  "scenario_id": "1",
  "sequence_id": "demo-001",
  "actions": [{"seq": 1, "action_name": "HttpServiceCheck",
               "target_node": {"subnet": "10.99.0.0/24", "ip": "10.99.0.1"}}]}'
# → 200 {"code":0,"message":"accepted","scenario_id":"1","sequence_id":"demo-001","dictionary_version":"validation/2"}

# ② 轮询状态（Q1，建议 2–5 秒一次）
curl -s "$BASE/api/v1/attack-sequences/demo-001?scenario_id=1"
# → {"data":{"state":"executing",...}} → 最终 {"data":{"state":"finished","steps":[...]}}

# ③ 拉取结果序列（Q2，state=finished 后）
curl -s "$BASE/api/v1/attack-sequences/demo-001/results?scenario_id=1"
# → {"data":{"results":[{"actual":"SUCCESS","stdout_digest":"HTTP 200",...}],"alerts_total":1}}

# ④ 分页拉取告警（Q3，用返回的 after_event_id 推进游标直到空页）
curl -s "$BASE/api/v1/snort-alerts?scenario_id=1&sequence_id=demo-001"
# → {"data":{"is_last":true,"total":1,"alerts":[...],"after_event_id":"net-xxx:1889"}}

# ⑤ 入库校准（数字平台侧逻辑）
```

## 1. 总体约定

| 项 | 约定 |
|:--|:--|
| 协议与编码 | HTTP/1.1，UTF-8 JSON |
| 信封 | 下发/受理为扁平对象（`{code, message, ...}`）；查询接口为 `{"data": {...}}`；错误为 `{"code": 非零, "message": "..."}` |
| 鉴权 | **默认关闭**（2026-11-24 定稿）——无需任何凭据。容器平台可选配置 `BRIDGE_VALIDATION_TOKEN` 启用 IF-01 Bearer 校验（届时错误凭据 401/1000）；查询接口恒开放。访问控制靠内网隔离＋端口准入 |
| 任务标识 | 一次实测任务由 `(scenario_id, sequence_id)` 唯一确定，所有接口必须携带。`scenario_id` 即容器平台当前**运行中**的 CORE session_id |
| 幂等 | IF-01 幂等键 = 上述二元组：同键同文返回原回执；同键异文 409/1005 |
| 数据保存承诺 | 任务/逐步结果/告警全部持久化（SQLite）；数字平台离线期间数据不丢失，恢复后查询即得全量 |
| 数据冻结承诺 | `state=finished` 后 Q1/Q2/Q3 返回内容**永不再变化**（含告警集合——封存时固定事件上界，迟到入库的告警不影响查询结果）；重复查询完全幂等 |
| 保存期限 | 任务/步骤：永久；窗口内告警：随平台 events 表保留策略（90 天）——**应及时拉取入库** |
| 一期并发 | 每会话同时只允许一个未完成任务（1006 拒绝第二个）；不同会话互不干扰 |

## 2. 对接前置条件

### 2.1 容器平台侧配置（全部可选，默认即查可用的拉模式）

| 环境变量 | 默认 | 配置后效果 |
|:--|:--|:--|
| `BRIDGE_VALIDATION_TOKEN` | 不配置 | 配置后 IF-01 启用 Bearer 校验（可选加固）；未配置 = 开放 |
| `BRIDGE_VALIDATION_CALLBACK_URL` | 不配置 | **旧推模式 opt-in 开关**：配置后封存时生成本任务 IF-02/03 投递记录并主动推送（拉模式查询不受影响）。默认不配置 = 零推送、投递表零新记录 |
| `BRIDGE_VALIDATION_CALLBACK_TOKEN` | 不配置 | 推模式启用时作为推送请求的 Bearer 凭据 |

变更配置后 `systemctl restart core-bridge` 生效。

### 2.2 拓扑侧前置标记（部署时固化，受理校验项）

| 标记 | 节点属性 | 约束 |
|:--|:--|:--|
| 序列执行节点 | `validation_source = true` | 每拓扑至多一个；本机 CORE 原生节点或 Docker 节点；全部动作由该节点发起 |
| HTTP 验证目标 | `validation_http_port`（1–65535） | 每拓扑至多一个；表示"该端口上有可验证的 HTTP 服务" |

标记方式：容器平台拓扑编辑页节点属性，或建节点 API 直接传字段；随部署固化进运行快照。无标记的拓扑照常运行，但受理验证任务报 409/1003。

### 2.3 Snort 观测（可选）

拓扑定义 `network_activity.probes` 声明探针（原生/Docker 节点接口被动抓包；内置 `verification` 无害验收规则集，特征串 `BRIDGE_IDS_CHECK`——预置检查请求自带该特征串，**验证与观测同源闭环**）。未部署探针的任务照常受理执行，仅 `observation_status=unavailable` 且 Q3 恒为空。

## 3. IF-01 攻击动作序列下发

```
POST /api/v1/attack-sequences
Content-Type: application/json; charset=utf-8
```

### 3.1 请求报文

```json
{
  "scenario_id": "1",
  "sequence_id": "demo-001",
  "actions": [
    {
      "seq": 1,
      "action_name": "HttpServiceCheck",
      "target_node": { "subnet": "10.99.0.0/24", "ip": "10.99.0.1" },
      "params": { "check_id": "web-health" }
    }
  ]
}
```

### 3.2 字段规格

| 字段 | 类型/约束 | 说明 |
|:--|:--|:--|
| `scenario_id` | 十进制正整数字符串 | 当前运行中的 CORE session_id；容器平台校验运行态 |
| `sequence_id` | `[A-Za-z0-9_.-]`，1–128 字符 | 每次新任务全新生成（建议 UUID） |
| `actions[]` | 1–64 步 | 按 seq 排序后必须为 1…N 连续，重复/缺号拒绝（1004） |
| `actions[].seq` | int ≥1 | 执行顺序 |
| `actions[].action_name` | ≤64 字符 | 必须在动作字典目录内（当前可执行：`HttpServiceCheck`）；未知/仅供对照条目 1002 |
| `actions[].source_node` | 可省略 `{subnet, ip}` | 省略时用部署标记的执行节点；提供时与标记节点运行接口核对，不匹配 1003 |
| `actions[].target_node` | 必填 `{subnet, ip, hostname?}` | 须对应部署标记的 HTTP 验证目标（subnet/ip 核对，目标地址在部署内唯一）；合法 IPv4 字面量 |
| `actions[].params.check_id` | 默认 `web-health` | 当前仅接受 `web-health` |

### 3.3 受理响应

```json
HTTP 200
{ "code": 0, "message": "accepted", "scenario_id": "1", "sequence_id": "demo-001",
  "dictionary_version": "validation/2" }
```

`code=0` = 已受理并完成预校验（此时**尚未执行**）。`dictionary_version` 受理时钉定的字典版本，随 Q2 原样回传。

### 3.4 错误码（实测值）

| code | HTTP | 触发条件 | 处理建议 |
|:--|:--:|:--|:--|
| 0 | 200 | 受理成功 | — |
| 1000 | 401 | 凭据无效（**仅容器平台配置了 Token 时可能出现**；默认鉴权关闭不会返回） | 核对凭据配置 |
| 1001 | 409 | 会话不存在/未运行；运行实例已变化；会话缺少运行中的部署 | 确认会话后重发新 sequence_id |
| 1002 | 400 | 动作名不在字典目录（或为仅供对照的参考条目） | 中止并告警，核对字典版本 |
| 1003 | 409 | 节点未标记/已离开会话/请求地址与运行接口不匹配/目标地址部署内不唯一 | 检查拓扑标记与请求地址一致性 |
| 1004 | 400 | 请求格式无效（缺字段/类型错/seq 不连续/超 64 步） | 修正报文 |
| 1005 | 409 | 同幂等键但报文内容不同 | 核对 sequence_id 是否复用 |
| 1006 | 409 | 该会话已有未完成任务（一期串行） | Q1 轮询等待当前任务完成 |
| 1501 | 503 | CORE 会话状态暂不可确认 | 瞬时问题，重试；持续失败联系容器平台运维 |

校验顺序：格式校验（1004）先于鉴权（1000，仅启用时）。

## 4. Q1 任务状态与步骤查询

```
GET /api/v1/attack-sequences/{sequence_id}?scenario_id={scenario_id}
```

**用途**：随时查询进度，决定何时拉取 Q2/Q3。未结束任务也可查询（返回当前已发生的状态）。任务不存在 → `404 {"code":1001,"message":"任务不存在"}`。

```json
HTTP 200
{ "data": {
    "scenario_id": "1", "sequence_id": "e2e-v2-003",
    "state": "finished", "observation_status": "complete",
    "dictionary_version": "validation/2",
    "source_node_id": 2, "target_node_id": 1,
    "steps": [
      { "seq": 1, "action_name": "HttpServiceCheck", "state": "SUCCESS",
        "reason": null, "duration_sec": 0.165 } ] } }
```

| 字段 | 说明 |
|:--|:--|
| `state` | `accepted` / `executing` / `finished`（结果冻结） |
| `observation_status` | `complete` / `partial` / `unavailable`；未结束任务可为 null |
| `steps[].state` | `pending` / `running` / `SUCCESS` / `FAIL` / `SKIPPED` |
| `steps[].reason` | 失败/跳过原因：`http_check_failed` / `http_check_timeout` / `node_or_interface_unavailable` / `interrupted_outcome_unknown` / 前序失败说明；成功为 null |

## 5. Q2 执行结果序列查询

```
GET /api/v1/attack-sequences/{sequence_id}/results?scenario_id={scenario_id}
```

**用途**：任务结束后拉取整条结果序列入库校准。**响应结构与 V1.0 IF-02 payload 一致**（入库代码可复用）。

```json
HTTP 200
{ "data": {
    "scenario_id": "1", "sequence_id": "e2e-v2-003",
    "dictionary_version": "validation/2",
    "state": "finished", "observation_status": "complete",
    "results": [
      { "seq": 1, "action_name": "HttpServiceCheck", "actual": "SUCCESS",
        "exit_code": 0, "reason": null,
        "started_at": "2026-11-24T08:08:30.022Z", "ended_at": "2026-11-24T08:08:30.186Z",
        "duration_sec": 0.165, "source_node_id": 2, "target_node_id": 1,
        "stdout_digest": "HTTP 200" } ],
    "alerts_total": 1 } }
```

| 字段 | 说明 |
|:--|:--|
| `results[].actual` | `SUCCESS` / `FAIL`（已尝试失败）/ `SKIPPED`（前序失败被跳过） |
| `results[].exit_code` | 有真实退出码传整数；未启动/未知传 `null` |
| `results[].started_at / ended_at` | UTC RFC3339 毫秒；未执行传 `null`；`duration_sec` 未执行传 0 |
| `results[].stdout_digest` | 输出摘要（如 `HTTP 200`），可选 |
| `alerts_total` | 观测窗口内告警总数（与 Q3 `total` 对账一致） |

**语义保证**：
- `finished` 后冻结：重复查询返回完全相同内容
- 未结束（accepted/executing）即查询：**只返回当前已完成步骤**——进行中步骤不进入 `results`、不误标终态，`state` 字段提示稍后再取
- `alerts_total` 含迟到入库防护（封存后固定）

## 6. Q3 Snort 告警分页查询

```
GET /api/v1/snort-alerts?scenario_id={scenario_id}&sequence_id={sequence_id}&after_event_id={event_id}&limit=100
```

| 参数 | 必填 | 说明 |
|:--|:--:|:--|
| `scenario_id` / `sequence_id` | 是 | 任务定位 |
| `after_event_id` | 否 | 增量游标：只返回该 event_id 之后的事件（首次不传取全部）；非法格式 400/1004 |
| `limit` | 否 | 默认 100，上限 500（超出收敛到 500） |

```json
HTTP 200
{ "data": {
    "scenario_id": "1", "sequence_id": "e2e-v2-003",
    "observation_status": "complete", "is_last": true,
    "total": 1, "after_event_id": "net-xxx:1889",
    "alerts": [
      { "event_id": "net-xxx:1889", "probe_id": "probe-verify", "seq": 1,
        "ts": "2026-11-24T08:08:30.168Z", "sid": "1:1000001", "priority": 0,
        "src_ip": "10.99.0.10", "src_port": 44350, "dst_ip": "10.99.0.1", "dst_port": 80,
        "proto": "TCP", "msg": "Bridge IDS verification" } ] } }
```

| 字段 | 说明 |
|:--|:--|
| `observation_status` | `complete` / `partial` / `unavailable`（finished 任务回放封存值，不随探针后续状态漂移） |
| `is_last` | `true` = 已到窗口末尾；游标推进到本响应 `after_event_id` 再拉一次得空页即完成全量 |
| `total` | 游标之后（含本页）的告警总数 |
| `after_event_id` | 本页最后一条的 event_id（空页时回显请求游标）——下一页请求直接携带 |
| `alerts[].event_id` | `<run_id>:<事件id>`，接收端去重键 |
| `alerts[].seq` | 可唯一归属某步时为该步 seq（五元组＋步骤时间窗唯一归属）；否则 `null` |
| `alerts[].ts` | UTC RFC3339 毫秒，**抓包时间**（非入库时间） |
| `alerts[].sid` | 规则标识 `GID:SID`；`priority` 为规则优先级 |

**错误**：任务不存在 404/1001；游标格式无效 400/1004。
**执行中任务**：以开放观测窗口返回已入库告警（不报错）。**封存后**：固定事件上界，迟到入库不改变 total/alerts/游标。

## 7. 任务生命周期与执行语义

```
accepted ──执行──> executing ──全部步骤完成/中断封存──> finished（数据冻结）
    │                    │
    └── (会话不可用等) ──┴──> 封存为 finished（reason 记录中断语义）
```

受理后容器平台自动执行，数字平台无需再下发任何指令：

1. **执行节点**：全部动作在部署标记的 `validation_source` 节点内执行（nsenter 进入其网络命名空间）
2. **逐步记录**：每步记录 started/ended（UTC RFC3339 毫秒）、duration_sec（单调时钟）、exit_code、reason
3. **失败即停**：某步 FAIL 后后续步骤记 SKIPPED（reason 注明前序失败）
4. **观测窗口**：受理时记录探针基线与事件游标；窗口 = 首步开始至末步结束＋收集宽限期（2s）
5. **告警归属**：窗口内、命中部署内探针、且源/目的五元组可唯一归属某步的告警标记 `seq`；无法唯一归属的 `seq=null` 保留在窗口观测中
6. **会话异常**：会话停止/被替换/容器平台中断时任务立即封存——已完成步骤保留事实，中断且无法确定结果的记 FAIL（`reason=interrupted_outcome_unknown`），随后照常可查
7. **判定基准**（一期 HttpServiceCheck）：对 `<ip>:<port>` 发起受限 HTTP GET——2xx 且退出码 0 → SUCCESS；连接失败/超时 → FAIL（`http_check_failed` / `http_check_timeout`）

## 8. 联调与验收清单（全部实测通过）

| 编号 | 场景 | 通过条件 | 实测 |
|:--|:--|:--|:--|
| 01 受理与执行 | 带标记的运行拓扑下发预置检查 | IF-01 code=0；Q1 → finished；Q2 SUCCESS＋`stdout_digest="HTTP 200"` | ✓ 2026-11-24（shellshock 靶标＋kali 执行节点） |
| 02 告警与归属 | 拓扑带 Snort 探针执行检查 | Q3 真实告警（sid=1:1000001）、seq=1 正确归属、observation complete | ✓ |
| 03 分页与游标 | limit=1 → 推进游标 → 空页 | `is_last` 翻转；非法游标 400/1004；任务不存在 404/1001 | ✓ |
| 04 数据冻结 | finished 后重启容器平台服务再查询 | 三接口返回与重启前一致；迟到入库不改变结果 | ✓ |
| 05 执行中可查 | executing 任务带告警查询 | Q2/Q3 均 200；Q2 只含已完成步骤 | ✓ |
| 06 拉模式纯净 | 未配回调执行完整任务 | 投递表零新记录；三项查询正常 | ✓ |
| 07 失败与中断 | 服务不可用/会话中断 | FAIL＋SKIPPED；reason 区分；中断后已完成步骤可查 | ✓ 单元测试 |
| 08 幂等与鉴权 | 同键重发/同键异文/无凭据/错凭据 | 幂等回执；1005；鉴权关闭全放行（配置 Token 后 401/1000） | ✓ |

## 9. 与 V1.0/V1.1 的关系

| 项 | V1.0/V1.1（推模式） | 本文档（V2.0 拉模式，当前契约） |
|:--|:--|:--|
| 结果获取 | 数字平台实现 IF-02 接收端 | Q2 查询调用，**无需接收端** |
| 告警获取 | IF-03 接收端（批/确认） | Q3 分页查询 |
| 完成感知 | IF-02 到达隐式感知 | Q1 轮询 `state=finished` |
| 回调/凭据配置 | 必须提供 | **全部取消**（推模式保留为容器平台侧 opt-in，见 §2.1） |
| 中断补发 | 容器平台重试队列 | 查询天然幂等，重查即可 |
| 入库校准 | 不变 | 不变（数据获取从被动接收改为主动拉取） |

历史投递数据（validation_deliveries）在拉模式下不再产生新记录；存量记录仅容器平台侧可见（任务列表端点），数字平台无需关心。
